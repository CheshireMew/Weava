# Weava 管理后台

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

网站站主在 Windows 浏览器中管理自己的站点。日常工作包括写作、查找和修改内容、组织页面与媒体、发布更新，以及查看统计和维护站点。

## Product Purpose

为 Weava 提供以内容为中心的管理界面，让站主在同一套工作流程中完成编辑、检查、预览与发布。此次优化覆盖全部管理后台，包括登录、内容与页面编辑、布局、内容类型、分类标签、媒体、评论、网址别名、发布计划、外观导航、统计、搜索检查、运行备份和账户。

## Operating Context

现有 React 管理后台与 Astro 访客网站共用 TypeScript 核心和结构化 API。站点实例的数据、文章和媒体独立保存；界面可以在本地浏览器运行。当前验收平台为 Windows。

## Capabilities and Constraints

保留真实内容和数据，以及工作稿、历史版本、预览、发布、批量操作和筛选。按用户于 2026-11-04 的要求移除后台页面列表、页面搭建器及模板布局管理；关于本站和友情链接使用网站设置中的固定表单，发布后自动更新固定前台界面并显示入口。旧站页面记录和公开网址保留。不引入内置 Agent、聊天入口或模型运行时。保留键盘操作、明确焦点、原生弹窗和窄窗口适配。

## Brand Commitments

名称为 Weava，界面以中文为主。2026-11-04 用户明确指定以其 Substack 截图为当前视觉参考，保留 Weava 功能与菜单结构；该选择覆盖此前蓝灰配色与紧凑表格构图。用户明确否定原有灰绿配色和本次未经方向确认的灰紫改版，要求严格按 Impeccable 流程选择与验证整套后台设计。保留准确的功能术语，减少多余的副标签和解释性装饰文案。

## Evidence on Hand

现有后台源码位于本目录 src，产品与流程文档位于仓库 README.md 和 docs。用户提供了内容列表页截图，并授权通过本地浏览器检查界面。隔离预览可以使用明确标记的测试站点和示例内容，不改变真实站点数据。

## Product Principles

- 内容编辑和发布任务决定布局与操作优先级。
- 相同操作在不同页面采用一致的控件与反馈。
- 重要状态通过文字和可识别的视觉差异共同表达。
- 设计改动以用户确认的方向和实际渲染评审为依据。
