# 账户与网站防护

Weava 使用单站主账户，不开放访客注册，无通用默认密码。首次启动在本机终端显示一次性设置链接，站主打开后自行填写账户名和密码；忘记密码时由本机 CLI 重新签发重设链接，也可使用原有离线恢复命令。后台“账户”提供资料、改密、登录会话撤销、私有后台入口、外部工具令牌轮换、账户记录和可选两步验证。改密与敏感操作需要当前密码，两步验证启用后也需要验证码或一次性恢复码。密码、会话令牌和两步验证密钥不进入公开 API；完整备份包含恢复账户所需的数据与密钥。丢失验证器时优先用恢复码，步骤见[运行与恢复](operations.md)。

设置链接使用 256 位随机令牌，数据库仅保存摘要，10 分钟后失效。重新签发、账户凭据变化或成功使用都会使原链接失效；提交在事务内再次校验，避免并发或密码派生期间过期后重复使用。网页立即移除地址中的令牌，只在页面内存保留，经同源 JSON 请求提交，不写入本地存储。链接只能用于指定的初始化或重设，不能访问其他管理接口，也不会自动创建登录会话。成功提交撤销原会话，站主随后正常登录；默认保留两步验证，只有本机明确使用 `--reset-two-factor` 才会关闭。没有公开签发接口，不支持任何人先打开后台就抢占账户。

新密码统一至少 15 个 Unicode 字符，使用本地常见密码名单和明显重复模式检查；保留密码中的空格，不对旧密码强行改写。没有将密码外发核验完整泄露密码库，不将有限本地名单描述为覆盖所有泄露密码。登录与敏感验证分别采用持久化来源/全局限流、并发上限和逐步延长的短期等待，响应提供准确重试时间。浏览器使用 HttpOnly、SameSite=Strict Cookie，HTTPS 连接或受信代理报告 HTTPS 时设置 Secure；线上 TLS 仍由部署配置提供。

退出会话、改密、两步验证变更及账户恢复由服务端撤销对应网页登录。CLI 使用独立令牌，常规改密不会轮换它；凭据疑似泄漏时可同时撤销全部网页登录并轮换 CLI 令牌。自定义入口只减少扫描，所有后台 API 始终独立认证。旧入口返回 404，公开接口不返回新入口。验证器二维码在本机生成，恢复码仅一次显示，可复制、下载和验证身份后重新生成；新码替换全部旧码。账户记录仅保存固定事件及时间、来源，不保存验证秘密。

管理写请求采用 JSON，并在扩展处理之前检查浏览器来源的协议和端口。管理页限制外站嵌入、脚本及连接，允许同源设计画布。登录与敏感账户操作分别限流。公开错误不返回内部路径，公开健康检查不暴露本机目录或进程身份。私密内容及其专用媒体对未登录访客返回 404；私密内容同时退出访客搜索、RSS、站点地图与导航。

正文清理禁止脚本与危险网址。上传会核对基础文件签名；SVG 与 HTML 附件通过隔离响应提供，PDF 等文件作为附件下载。WordPress 远程附件拒绝本机、内网和保留地址，每次重定向重新校验并固定 DNS 结果，设置时间、大小和跳转次数上限。已有本地附件可通过后台目录输入或 CLI `--media-dir` 导入，目录链接不得越过选定目录。

私密媒体按浏览器实际请求的 URL 建立权限索引，处理 HTML 实体、Markdown 渲染和 URL 规范化；旧站点通过数据库版本 12 修复当前内容、历史修订及归档中的引用。历史私密保护继续保留，只有当前已发布的公开内容共用该媒体时才公开提供。

公开统计和爬虫日志共用持久化来源/全局请求及事件预算，重启不会清除额度；来源记录有数量上限。默认每来源每分钟 120 次请求/600 个事件，全站每分钟 1200 次请求/6000 个事件；每天每来源 20000 个、全站 100000 个事件。超过额度返回 429 和 Retry-After。统计数据库及 WAL 达到约 1 GiB，或磁盘可用空间不足 512 MiB 时暂停采集并返回 503；采集容量检查最多缓存一秒，容量阈值可能有少量超出。页面和已存统计仍可读取，不自动删除历史。部署时可按实际流量调整 `WEAVA_ANALYTICS_DAILY_EVENTS`、`WEAVA_ANALYTICS_MAX_BYTES`、`WEAVA_ANALYTICS_MIN_FREE_BYTES`，不允许关闭容量保护。爬虫日志在受限时直接跳过，避免影响正常页面响应。

CSV 导出把以公式标记开头的外部文字作为文本处理，覆盖前置空白/控制字符及全角标记；数字值保持数字。危险文字单元格会在引号内增加制表符，适合在 Excel 查看，程序导入时需保留其文本含义。

HTML 广告在不具有同源权限的 sandbox iframe 内运行，不能读取主页面、会话或操作后台；普通结构化广告仍直接展示。HTML 原文保留，旧广告自动使用隔离响应。广告中的脚本只能使用独立框架的 DOM；依赖访问父页面或同源 Cookie 的旧广告需改用独立广告接口。扩展则属于受信任的服务器代码，具有服务账户权限，只能安装自己审查过的扩展。服务器入口、文件权限与反向代理配置见[运行文档](operations.md#windows-服务器部署)。

回归入口为 `tests/security-repairs.test.ts`，覆盖编码地址、当前公开共用规则、旧修订与归档迁移、持久额度、磁盘保护、CSV 和 HTTPS 边界。`scripts/check-security-repairs.ts` 使用已选择的生产程序、独立测试站点、Windows nginx 和自签名测试证书，通过真实 TLS 请求及隔离浏览器检查同样的安全边界；工具路径、证书位置和输出目录见脚本开头。它不读取真实站点，不验证公网证书或防火墙。

| esbuild | 0.28.2，满足现用 Vite 的兼容范围 |

最终官方 npm 生产依赖审计的已知漏洞数为 0，依赖兼容检查通过。审计原始结果保存在 `D:/Tools/cache/weava/personal-site-dependency-audit-final-20261101.json`。调查时曾验证 deepmerge 的本地修补，最终由官方依赖升级替代，活动安装链不使用自维护补丁，也没有屏蔽漏洞公告。

新增回归测试通过应用真实正文清理入口检查危险媒体网址，并测试超长未闭合引用的解析耗时。账户、上传、来源、私密资源和附件下载分别有边界测试及隔离实例 HTTP 证据。完整结果见[交付与验收记录](personal-site-completion.md)。这些证据覆盖当前源码、锁定依赖和 Windows 本地运行；服务器 HTTPS、代理和部署设置仍需由实际部署配置保证，不表示对未来漏洞作永久保证。
