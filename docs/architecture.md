# 架构与数据

`apps/web` 是 Astro Node 服务，处理访客页面、预览、媒体与接口；`apps/admin` 是独立 React 构建；`packages/core` 不依赖这两个界面框架。`contracts` 只包含可以在浏览器使用的类型和校验规则。CLI 与后台调用同一套服务。

站点数据库与框架分开。`weava.sqlite` 保存通用记录、不可变修订、公开版本、任务和搜索；`analytics.sqlite` 保存访问事件。SQLite 启用 WAL、外键及事务。媒体保存为普通文件，上传生成的轻量图片存于 media/optimized。

记录的 `revision` 是全局递增的版本编号。保存必须带回读到的编号；两个窗口提交同一旧编号时，后一个收到 409。移除字段定义不会物理清除旧字段值。不兼容的字段类型变更会列出受影响内容。

普通正文的有效来源为 Markdown、Lexical 或 HTML 中的一种；包含区块的页面和内容以 blocks 为当前正文。迁移保留的原 document 不参与当前区块正文的搜索和公开媒体判断。渲染结果可以重建。可视化编辑器不执行来源脚本，复杂源码不会在模式切换时被静默转换。

布局作为独立、带修订的记录管理，分为模板、共享区域与区块组合。公开版本固定布局对象，换主题不会删除内容。模板必须有且只有一个正文占位，共享区域引用在保存和发布时检查缺失、循环及绑定属性；发布还使用同一实际模板渲染器检查候选页面。布局发布不选择内容或设置工作稿。

发布先固定工作稿修订，生成正文、路由、搜索和设置的候选版本，校验区块属性、实际区块渲染和内容引用，最后通过事务切换公开版本。发布任务的完成记录与版本切换在同一事务提交。中途失败不改变当前公开版本。每个请求读取固定的公开版本；运行中的程序按版本缓存不可变快照，不缓存可能过期的“当前版本”指针。

数据库版本 3 将公开内容、设置、类型、分类、布局和路由存成按散列复用的不可变对象；公开版本只保存对象清单。未改内容不会因下一次发布再复制正文和全文索引。搜索包含页面自身及其引用的共享区域，索引随版本固定；共享文字变化只新增对应搜索对象，不复制未改文章。旧完整快照在升级前保存数据库副本，再转换为相同格式，保留版本编号和回退入口。历史维护先校验归档再移出旧版本，恢复不切换公开页面；旧搜索表不继续写入，归档相应版本时一并整理其索引。

发布单篇内容不会顺便发布站点设置工作稿，发布设置不会选择文章工作稿。全站发布会更新已有公开内容与设置，新草稿需要明确发布。发布摘要会记录查看时的工作稿和公开版本，提交时变化则要求重新查看。撤下不删除源内容；历史版本恢复为工作稿，公开版本回退则直接切换既有快照和路由历史。

冲突恢复使用共同来源修订、本地内容与服务器当前修订进行三方合并，正文作为完整单元处理。冲突选择必须明确，保存再次核对服务器修订；不直接覆盖新版。历史查看只读，恢复仍经过正常内容校验并创建新工作稿。

标准 WXR 导入先严格解析 XML、转换区块与稳定关联，再用相同导入事务完整预检。实际附件处理先准备文件，内容、分类、类型、媒体记录和评论最后一起提交；失败时公开版本不变，准备过的文件保留，便于恢复和维护。原始 WXR 单独归档，未知来源功能列入报告并阻止未经检查的发布。来源主题和插件程序不会被当作站点代码执行。

定时发布保存指定的不可变修订。领取计划、公开版本切换及完成状态在同一事务中提交，中断会整体回退，启动后补执行到期计划；之后保存的新工作稿不会被该计划意外发布。计划失败保留原公开版本并记录原因，可以取消或重试。

公开页面由 Astro 输出 HTML；菜单、搜索和图片放大仅加载必要脚本。React 和 Lexical 只属于管理后台。正式环境一个 Node 服务运行一个站点；后台任务由受管理的子进程执行，通过 SQLite 共享任务状态，不依赖 Redis。

数据库迁移版本在 schema_migrations 中登记。遇到比程序更新的数据库版本会拒绝继续处理；修改结构前应创建备份并提供版本迁移。框架升级、站点内容发布和数据恢复是三个独立操作。
