# 性能优化实施记录：2026-11-03

原报告的 15 项均已实施。优化保留原有技术栈、不可变发布版本、修订冲突、私密媒体和导入原子性；主要调整计算位置、数据索引、缓存边界和文件处理方式。当前验证平台为 Windows，测试数据与证据位于 D:/Tools/cache/weava。

| 报告项 | 实现 |
| --- | --- |
| 1 发布预览及重复准备 | 发布查看在计算进程准备一次，保存十分钟有效的增量候选；提交复用候选并核对工作稿、公开版本、选项和渲染程序。推荐使用分类/标签索引，稳定校验结果按内容及依赖复用，扩展校验继续执行 |
| 2 定时/计划发布与事务 | 网站定时器只查到期索引并入队；准备、散列、搜索文本和媒体引用在写事务前完成，最终事务重新核对版本，并原子切换版本、任务和计划状态 |
| 3 维护及媒体引用 | 保存、发布和历史恢复维护引用索引，历史增量补齐；引用查询和空间盘点移入计算进程。盘点只解析新增或变更来源，缓存档案引用，空间总量从字节数索引读取 |
| 4 后台静态资源 | 带版本的程序资源使用 immutable 缓存、ETag、Last-Modified、304；异步读取和有容量限制的 gzip 结果缓存，压缩与原始响应的 ETag 分开 |
| 5 媒体缓存校验 | 支持 ETag、Last-Modified、304、条件请求优先级和 If-Range；原有私密授权、Range 与 HEAD 行为保留 |
| 6 统计报表 | 数据库聚合取代完整事件数组；会话边界、访客/会话去重、生命周期计数和事实索引增量维护。查询范围通过变更记录增量更新，较大范围使用磁盘临时存储，访客汇总只返回前一百项，轨迹继续数据库分页 |
| 7 短任务及调度 | 最多两个常驻计算进程、有界等待队列和超时，复用连接；查询不创建永久任务或日志。可靠写任务保留持久队列，任务状态有索引，空轮询只读；单个任务日志仍有容量上限 |
| 8 Newsletter | 公开目录、分类数量和精选按版本复用；仅需要时读取热门排名，十秒复用计数与排序；展示项按需读取封面，推荐通过编号索引定位 |
| 9 重复内容派生 | 公开纯正文直接使用发布 HTML；文档渲染、目录、图片属性和补齐后的 HTML 使用有容量限制的缓存，媒体修订变化后失效 |
| 10 公开版本读取 | 新版本存轻量目录，旧清单也支持元数据读取；正文按需加载，同散列对象最多复用约 32 MiB，版本视图和路由索引按不可变对象复用 |
| 11 内容查询与搜索 | 元数据目录支持数据库筛选、排序、计数和分页，每页最多一百项；FTS 命中保留在数据库。规模不超过 8,192 篇时只缓存最近一次搜索的命中，版本或查询变化后更新 |
| 12 后台首屏依赖 | 登录入口与工作区拆分，类型、设置、运维面板懒加载；会话传输使用轻量契约，Zod 改为可裁剪的命名空间导入，继续保留请求和响应校验 |
| 13 编辑与恢复 | 修改时进行结构比较并保存 dirty 状态，读取 dirty 无需序列化；画布只在值变化时更新。草稿按文章异步存入 IndexedDB，合并连续修改，保留旧副本迁移、存储失败提示、离开前兜底和冲突恢复 |
| 14 上传 | 浏览器和 CLI 使用相同的二进制分块协议，支持上传位置、进度、继续上传、幂等处理及失败重试。网站异步暂存，工作进程按文件校验与处理；旧版大 base64 JSON 也先落盘，在有并发上限的计算进程解码 |
| 15 大文件与初始化 | 文件散列按 1 MiB 分块，JSONL 逐条读取；WXR 文件按 64 KiB 读取，每项解析后释放 XML 节点，原始条目和转换正文放入两份可复用磁盘工作区。批量导入复用引用表并避免整组重复克隆；高亮器和语言按需初始化 |

## 本机复测

沿用原报告的机器、Node 版本和合成样本。以下为操作耗时中位数，重操作三次采样。它们不是线上 HTTP 延迟或浏览器输入耗时；微秒级及小于数毫秒的差异容易受到系统负载影响。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 3,000 篇，准备单篇发布 | 17,070.7 ms | 731.0 ms |
| 3,000 篇，发布查看所需工作 | 两次准备 38,278.8 ms | 查看并读取候选 1,374.4 ms |
| 3,000 篇，清空版本缓存后读取 | 98.0 ms | 37.4 ms |
| 3,000 篇，文章模板渲染 | 5.33 ms | 0.245 ms |
| 3,000 篇，普通公开分页 | 2.96 ms | 2.06 ms |
| 3,000 篇，高频词搜索热查询 | 9.88 ms | 4.13 ms |
| 100,000 条事件，30 天报表与对比期 | 11,136.5 ms | 1,913.1 ms |
| 100,000 条事件，单日报表 | 971.7 ms | 128.6 ms |
| 100,000 条事件组，调用后 V8 堆快照 | 625.4 MiB | 31.5 MiB |
| 同组，调用后进程 RSS 快照 | 870.4 MiB | 420.1 MiB |
| 10,000 个修订，媒体引用热查询 | 132.7 ms | 0.90 ms |
| 10,000 个修订，空间盘点热查询 | 111.2 ms | 34.4 ms |
| 100,000 条完成任务，空队列检查 | 9.81 ms | 0.040 ms |
| 空实时统计，源码进程首次往返 | 1,418.6 ms | 351.1 ms；进程复用后平均 0.69 ms |
| 后台首次静态依赖，内存编译估算 | 851,140 字节 | 338,482 字节 |
| 同上，逐文件 gzip 合计 | 215,574 字节 | 105,167 字节 |

发布查看和候选读取的测量与旧版“两次准备”覆盖的是相应实现的工作量；正式接口另有 IPC、扩展检查和响应编码。3,000 篇时源码计算进程首次查看约 5.25 秒，复用后约 2.47 秒，网站调用线程可继续处理其他请求。新流程另测得最终数据库写事务中位数约 44 毫秒，事务外存储准备约 257 毫秒。

50 万字符文章的标题修改，EditSession 核心中位耗时约 0.003 毫秒；同次运行中继续调用旧本地档案写入逻辑约 2.82 毫秒。新编辑路径每次修改没有同步草稿写入，异步持久化按短间隔合并。这项测量没有包含 React、编辑器、IndexedDB 的真实提交或页面布局，不能据此宣称浏览器输入延迟为该数字。

另以 132,255,805 字节（约 126 MiB）的 WXR 文件、1,000 篇内容执行完整导入预检，在 `--max-old-space-size=768` 下通过，耗时约 74.0 秒；调用后的堆快照约 219 MiB。该测量验证文件读取和转换能在此堆限制内完成，未测网络附件下载速度。文件散列使用固定大小缓冲，不能再以文件大小决定 Buffer 大小。

## 验证与边界

最终执行 `node node_modules/vitest/vitest.mjs run`，53 个测试文件、311 个测试全部通过，耗时 205.84 秒。TypeScript 检查、API 文档一致性检查通过；Newsletter 使用本机 Astro 编译器在内存中转换，诊断为空。旧数据库升级的重复索引与精简表结构情况也已通过回归。

回归覆盖统计结果与旧实现逐字段对照、时区及夏令时、历史变更增量补齐，候选失效、异步定时发布、事务回退、正文按需读取、查询排序和筛选一致性，媒体条件响应与上传继续处理，草稿迁移和写入失败，WXR 重复导入及备份恢复。新测试还验证计算查询不创建永久任务或日志。

主数据库结构版本为 11。升级前沿用既有数据库副本保护机制。公开目录兼容旧版清单；草稿仅在 IndexedDB 提交成功后迁移旧恢复副本。cache 下的维护索引和 WXR 工作区可以重建，不进入备份；原始导入资料、内容历史和已有任务日志继续保留。此次没有执行真实实例清理、部署、构建或打包，也没有操控浏览器，因此没有新增生产构建体积、LCP、INP、CLS 或真实输入延迟结论。
